What it is

An observational layer for wireless telemetry

Professional wireless systems already talk over IP: RF levels, battery reports, mute flags, identity fields, and a long tail of vendor-specific values. That talk is fragmented, late, and easy to over-trust. NodeScope discovers, decodes, timestamps and translates those values into a manufacturer-neutral state model — then shows the engineer what the software actually knows.

The research question is manufacturer-neutral. The first demonstration is not. The scoped public demo is NodeScope — Shure Edition, coming soon.

Capabilities in the current build

Drawn from the v2.2.0 user guide. Presentation is required to stay readable at three metres.

Channel grid

Up to 32 live tiles.

Each tile shows RF-A / RF-B, battery, audio level, mute state and fault status together, with talent name, role and priority when assigned.

Smart alerts

State machine, not a car alarm.

Battery depletion trends, RF warnings and faults, audio dropouts and unexpected mute. Persistence, hysteresis and recovery are first-class states.

Mic check

Structured pre-show pass.

OK / Watch / Fault marking, engineer and venue metadata, timestamped log, and an exportable PDF report.

Talent profiles

Human context on the wire.

Named performers with photos, roles and priority. Per-talent battery and RF thresholds. Lead channels escalate alerts so they are not lost in a busy list.

WebUI remote

HTTP + WebSocket on the LAN.

A tablet at FOH or a phone in the wings can watch channels and manage talent. Visibility is not access. Bind to localhost by default.

MQTT and OSC

Versioned output contracts.

Channel, device, alert and system state published to a broker. OSC for consoles and show control. Publishing outward does not make NodeScope a control bus.

How the data is treated

Three interface jobs, not one pipe

  • ASK — request / response. You know the answer at the moment you asked.
  • LISTEN — unsolicited or subscribed stream. Silence can mean “nothing changed” or “the conversation died.”
  • DISCOVER — announcement, browse or scan. Absence is a hypothesis, not proof the device does not exist.

Every accepted value carries a timestamp of observation, not of display. A frozen healthy reading is a comms problem in costume. Stale is a state. “I don’t know” is a first-class display value.

Six principles

The acceptance test for later features

  1. Preserve before translating. Raw values stay. Derived state is an opinion with a timestamp.
  2. Timestamp before trusting. Age is part of the value. No age, no trust.
  3. Identify before addressing. The device is not its current IP address.
  4. Compare carefully. Shared English names do not make quantities comparable.
  5. Add context before alerting. Role, history, persistence, recovery.
  6. Observe before controlling. No write path until the read path can admit uncertainty.

Alert types

Alerts fire and clear automatically. Inactive Shure slots with zero RF and zero audio are suppressed so unused receiver channels do not flood the list. Per-talent thresholds override the global defaults.

Alert Trigger Default
Battery critical Battery % below critical threshold 15%
Battery warning Battery % below warning threshold 30%
Battery depletion trend Drain rate suggests under 30 minutes remaining On for Lead / Important
RF warning Signal below warning level −85 dBm
RF fault Signal lost or dropout Immediate on loss
Audio dropout Programme seen, then silence for a sustained period −40 dBu silence
Mute active Transmitter muted while programme is expected Context required

Getting started

Demo mode in under two minutes

  1. Launch ETR-NodeScope. Status bar reads Ready.
  2. Actions → Toggle Demo Mode. Simulated Shure and Sennheiser devices appear.
  3. Choose the Demo audio generator in the output device dropdown.
  4. Ctrl+S or Actions → Start Services. Tiles animate with simulated RF, battery and audio.

Real hardware needs receiver IPs or auto-discovery, a Dante Virtual Soundcard or ASIO path on Windows, and a check against front-panel meters before anyone treats the screen as useful.
